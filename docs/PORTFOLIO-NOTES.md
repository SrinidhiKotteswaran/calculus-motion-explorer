# Maker portfolio notes

Motion Explorer is designed to be understandable from three layers of evidence:

1. **Working project:** the deployed web app demonstrates the interactive behavior.
2. **Codebase:** the repository shows the parser, AST, symbolic differentiation, numerical methods, and visualization code.
3. **Build evidence:** the build journal, screenshots, and technical notes show how the project evolved and what problems were solved.

For a future portfolio submission, the strongest media should show the project being built and investigated rather than simply presenting a polished landing page.

## Suggested media set

- early Python prototype screenshot
- parser/AST implementation screenshot
- symbolic differentiation example
- numerical error experiment
- Secant -> Tangent interaction
- analysis/integration experiments
- final working application

The final video should be short and technical. It should demonstrate behavior that is difficult to understand from a still image rather than functioning as a promotional reel.

## Suggested explanation

> I started with a small motion visualizer because I wanted to see calculus instead of only solving it on paper. As I experimented, the project became a computational laboratory: I built my own expression parser and symbolic differentiator, implemented numerical methods, and used the interface to investigate where those algorithms work and where finite precision changes the answer.

This is a planning document, not a submission. Final portfolio materials should describe the project accurately and only include work that was actually built and documented.
